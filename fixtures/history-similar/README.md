# `fixtures/history-similar` — the similar-content matcher's measured corpus (Slice 12c-ii)

Generated by `scripts/make_history_fixtures.sh`, alongside its `history-*` siblings. That script
runs `git`; it is a development tool, on the same side of the line as
`make_gitobj_fixtures.sh` and cloning the validation corpus. No Rust source may name it.

## Layout

`gitdir/` is a real Git directory under a plain name. It is **not** called `.git`, because Git
will not track files inside a nested `.git` — a fixture that stored one could not be committed at
all. A test copies `gitdir/` into a temporary directory, renames the copy to `.git`, and opens
that.

`inventory.json` carries the expected change rows and every one of them is **Git's own answer**,
read back out of *this fixture's committed bytes*. `ground_truth.json` is different in kind: it is
**hand-written**, it is not produced by this script, and it is what the precision test measures
against.

Identity and clock are fixed and synthetic — `Nerve Fixture <fixture@nerve.invalid>`, each commit
one hour after the previous one starting at 2026-01-01T00:00:00+0000. **No developer identity is in
any committed byte.** `config`, `index`, `logs/` and `hooks/` are not copied.

## What this exercises

12b's exact-content matcher pairs a deletion with an addition when the **blob oid** is the same.
12c-ii adds the case where content changed *and* moved, measured by `nerve-line-multiset`: split
both blobs on `\n`, drop a single trailing empty segment, build a multiset of the raw line bytes,
and take `numerator = Σ min(count_from, count_to)` over `denominator = max(lines_from, lines_to)`.
Admission is `numerator × 8 >= 7 × denominator` — integer arithmetic, no float anywhere.

Every file below is twenty distinct lines unless the case needs otherwise, so each numerator is a
count of shared line strings and every row of this table can be checked by hand.

| commit | change | shared / total | ground truth | admitted at 7/8 |
|---|---|---|---|---|

because its two blob oids are equal.

## Why the threshold is 7/8, and how c5 decides it

The gate is **false positives = 0**, and c5 is the pair that sets the number. Two unrelated
documents sharing a sixteen-line licence header measure `16/20`, which is exactly `4/5`. A threshold
of `4/5` admits it (`16×5 = 80 ≥ 4×20 = 80`) and the false-positive count stops being zero; `7/10`
admits it and c4's scaffold pair as well (`14×10 = 140 ≥ 7×20 = 140`). `7/8` clears both with margin
and still admits c1's `18/20`. The price is c2: a genuine move with twelve of twenty lines rewritten
falls below the threshold and is **published as a false negative** rather than bought back by
lowering the gate.

## `ground_truth.json` is hand-written and is not generated here

`scripts/make_history_fixtures.sh` builds this repository; it does **not** write
`ground_truth.json`. That file labels every candidate pair `rename`, `not_rename` or `unmeasurable`
by construction — the generator wrote one file out of the other, or it did not — and carries the
expected numerator and denominator for each. If it were emitted by the matcher, the precision test
over it would be Nerve agreeing with itself.

`inventory.json` is generated as usual and carries **Git's** answer for the change rows. It does
not carry similarity candidates or measurements: computing those here would be a second
implementation of the matcher living inside the fixture that grades it.

## What a test must assert

- **False positives = 0.** No pair labelled `not_rename` may be admitted. The test fails if one is.
- Exact-content and similar-content precision are **two tables**, never summed and never averaged.
- c2 is reported **as a false negative**, not quietly dropped.
- c6 keeps both pairings with `many_to` and c7 keeps both with `many_from`; neither is promoted.
- c11 records `pairs_considered = 0` — a copy is not a candidate, so its 19 shared lines never
  reach a measurement.
- c13 produces an `exact_content` row with `match_numerator IS NULL`, and **no** `similar_content`
  row for the same pairing.
- Every commit, including c0 and c11, has exactly one `git_rename_analysis` row.
- Anti-vacuity: the corpus contains admitted pairs, rejected pairs **and** unmeasurable pairs, so a
  matcher that returned nothing at all could not pass.

## What this fixture deliberately does not contain

- **No bound-exceeding case.** `MAX_SIMILARITY_DELETIONS` needs 65 deletions and
  `MAX_SIMILARITY_LINES` needs 50 001 lines; committing either would put a megabyte of generated
  text in the repository to test a constant. The bounds are fields on `SimilarityLimits` instead, so
  a test tightens them over *this* fixture and observes `refused_bound` end to end.
- **No `many_both` case.** The vocabulary has it and the unit tests over the classifier cover it,
  where it costs nothing.
- **No absent blob.** Deleting an object out of a committed fixture would make the fixture describe
  a repository Git itself would call broken; `history-missing` owns that shape, and the matcher's
  `blob-absent` path is covered by a unit test over an empty store.
