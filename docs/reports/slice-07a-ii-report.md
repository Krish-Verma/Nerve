# Slice 7a-ii — one word, two meanings

**Corrective slice.** Slice 7a shipped `nerve gaps` meaning **coverage gaps**. The SPA already had a
view labelled **"Gaps"** rendering `<Unresolved>` from `/api/unresolved` — unresolved references and
partial parses, which are **Nerve's own knowledge gaps**, not the repository's test gaps. A user
reading "Gaps" in the interface and running `nerve gaps` got different answers to what looked like
the same question.

## Delivered

- SPA view renamed **Unresolved** (`git mv`, nav label, heading, route `#/unresolved`, component).
  Behaviour unchanged — this is a naming correction. `#/gaps` no longer resolves, deliberately: the
  ambiguous word is gone from both surfaces.
- New **Coverage** view over `/api/gaps` (`#/coverage`), so the data Slice 6 ingests is finally
  visible in the product.
- Two cross-references in `Entity.tsx` / `Path.tsx` corrected; `apps/nerve-web/README.md` updated.
- Assets regenerated by `tools/embed.mjs` and re-embedded into the binary.
